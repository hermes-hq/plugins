# Plugin Development Guide

This guide walks you through creating, building, and testing a Hermes IDE plugin.

## Prerequisites

- **Node.js 20+**
- **npm**
- **Hermes IDE** installed (for testing)

## Quick Start

```bash
# 1. Clone the plugins repo
git clone https://github.com/hermes-hq/plugins.git
cd plugins

# 2. Copy the template
cp -r templates/basic plugins/my-plugin
cd plugins/my-plugin

# 3. Edit hermes-plugin.json with your plugin details
#    - Set a unique id (format: your-name.plugin-name)
#    - Set name, description, author
#    - Define commands, panels, and permissions

# 4. Install dependencies
npm install

# 5. Build
npm run build

# 6. Test locally — copy to Hermes IDE plugins directory
# macOS:
cp -r . ~/Library/Application\ Support/com.hermes-ide.terminal/plugins/your-name.my-plugin/
# Linux:
cp -r . ~/.config/com.hermes-ide.terminal/plugins/your-name.my-plugin/
# Windows:
# Copy to %APPDATA%/com.hermes-ide.terminal/plugins/your-name.my-plugin/

# 7. Restart Hermes IDE to load the plugin
```

## Dev Workflow (Recommended)

After building your plugin, copy it to the Hermes IDE plugins directory:

```bash
# Build
npm run build

# macOS:
cp -r . ~/Library/Application\ Support/com.hermes-ide.terminal/plugins/your-name.my-plugin/

# Linux:
cp -r . ~/.config/com.hermes-ide.terminal/plugins/your-name.my-plugin/

# Windows:
# Copy to %APPDATA%/com.hermes-ide.terminal/plugins/your-name.my-plugin/
```

> **Note:** Symlinks are not supported — the Tauri backend rejects them as directory traversal for security reasons. Always copy the plugin directory.

For faster iteration, use a build-and-copy script:

```bash
npm run build && cp -r . ~/Library/Application\ Support/com.hermes-ide.terminal/plugins/your-name.my-plugin/
```

Restart Hermes IDE after each rebuild to see your changes.

## Project Structure

```
my-plugin/
├── hermes-plugin.json   # Plugin manifest (required)
├── package.json         # npm package config
├── tsconfig.json        # TypeScript config (classic JSX runtime)
├── vite.config.ts       # Vite build config (IIFE output, React external)
├── src/
│   ├── activate.ts      # Entry point — exports activate() and deactivate()
│   └── MyPanel.tsx      # Optional panel component
└── dist/
    └── index.js         # Built IIFE bundle (generated by npm run build)
```

### Key Files

**`hermes-plugin.json`** — The plugin manifest. Declares your plugin's ID, name, version, commands, panels, permissions, and activation events. See the [Manifest Reference](./MANIFEST.md) for the full schema.

**`src/activate.ts`** — The entry point. Must export two functions:

```typescript
export function activate(api: HermesPluginAPI) {
  // Called when the plugin is activated
  // Use `api` to register panels, commands, etc.
}

export function deactivate() {
  // Called when the plugin is deactivated
  // Clean up any resources
}
```

**`vite.config.ts`** — Build configuration. The template comes pre-configured with the correct settings. You generally don't need to modify this.

## Build Configuration

Plugins are built as **IIFE** (Immediately Invoked Function Expression) bundles. This is required by the host app's plugin loader.

Key details:

- **React is externalized** — The host app provides React as `window.React`. Your plugin does not bundle React; it uses the app's instance.
- **Classic JSX runtime** — The TypeScript config uses `jsx: "react"` with `React.createElement`. Do not use the automatic JSX runtime.
- **IIFE footer** — The Vite config includes a footer that registers the plugin on `window.__hermesPlugins` so the host app can discover it.
- **No minification** — The template disables minification (`minify: false`) to keep the output readable for code review.

## Theming

Plugins must use the app's CSS custom properties for consistent appearance across all themes. **Do not hardcode colors** — they will look wrong when users switch themes.

### Available CSS Custom Properties

| Property | Purpose |
|----------|---------|
| `--bg-1` | Primary background |
| `--bg-2` | Secondary background |
| `--bg-3` | Tertiary background |
| `--text-1` | Primary text color |
| `--text-2` | Secondary text color |
| `--accent` | Accent color (buttons, links) |
| `--red` | Error/danger color |
| `--border` | Border color |
| `--radius-sm` | Border radius for small elements |
| `--font-mono` | Monospace font family |
| `--text-xs` | Extra small text size |
| `--text-sm` | Small text size |

### Using CSS in Plugins

Since plugins are IIFE bundles, you cannot use CSS file imports. Instead, inject CSS at runtime:

```typescript
const styles = `
  .my-plugin-container {
    color: var(--text-1);
    background: var(--bg-1);
    border: 1px solid var(--border);
    border-radius: var(--radius-sm);
    font-family: var(--font-mono);
    font-size: var(--text-sm);
  }

  .my-plugin-button {
    background: var(--accent);
    color: var(--bg-1);
    border: none;
    border-radius: var(--radius-sm);
    padding: 6px 12px;
    cursor: pointer;
    font-size: var(--text-xs);
  }
`;

let injected = false;

function injectStyles() {
  if (injected) return;
  const el = document.createElement("style");
  el.textContent = styles;
  document.head.appendChild(el);
  injected = true;
}
```

Call `injectStyles()` in your `activate()` function.

Alternatively, use inline styles with CSS custom properties as shown in the template's `MyPanel.tsx`.

## Working with the Plugin API

The `activate()` function receives a `HermesPluginAPI` object. Use it to interact with the host app:

```typescript
export function activate(api: HermesPluginAPI) {
  // Register a panel
  api.ui.registerPanel("my-plugin-panel", MyPanelComponent);

  // Register a command
  api.subscriptions.push(
    api.commands.register("my-plugin.doSomething", () => {
      api.ui.showToast("Done!", { type: "success" });
    })
  );

  // Use clipboard (requires permissions)
  api.subscriptions.push(
    api.commands.register("my-plugin.paste", async () => {
      const text = await api.clipboard.readText();
      // ... process text
    })
  );

  // Use persistent storage (requires "storage" permission)
  api.subscriptions.push(
    api.commands.register("my-plugin.save", async () => {
      await api.storage.set("lastInput", "some value");
    })
  );

  // Use settings (requires "storage" permission, auto-granted if settings schema exists)
  const all = await api.settings.getAll();
  api.subscriptions.push(
    api.settings.onDidChange("theme", (newValue) => {
      console.log("Theme setting changed:", newValue);
    })
  );

  // Make network requests (requires "network" permission)
  const data = await api.network.fetch("https://api.example.com/data");

  // Send notifications (requires "notifications" permission)
  await api.notifications.send({ title: "Done!", body: "Task completed." });

  // Access session info (requires "sessions.read" permission)
  const active = await api.sessions.getActive();
}
```

See the [Plugin API Reference](./PLUGIN-API.md) for the complete API documentation.

## Adding to the Registry

Once your plugin is ready:

1. Add an entry to `registry/index.json`:

```json
{
  "id": "your-name.my-plugin",
  "name": "My Plugin",
  "version": "1.0.0",
  "description": "What your plugin does",
  "author": "Your Name",
  "downloadUrl": "https://github.com/hermes-hq/plugins/releases/download/my-plugin-v1.0.0/your-name.my-plugin-1.0.0.tgz",
  "minAppVersion": "0.4.0",
  "permissions": []
}
```

2. Open a Pull Request. See [CONTRIBUTING.md](../CONTRIBUTING.md) for the full submission process and review criteria.

## Tips

- **Start from the template.** The `templates/basic/` directory has everything configured correctly. Don't set up a plugin from scratch unless you have a specific reason.
- **Keep permissions minimal.** Only request what you need. Plugins requesting unnecessary permissions are less likely to be approved.
- **Test with different themes.** Make sure your plugin looks correct in both light and dark themes by using CSS custom properties.
- **Add disposables to `api.subscriptions`.** This ensures they are cleaned up automatically when the plugin is deactivated.
- **Keep the source readable.** Submitted source code is reviewed by the Hermes HQ team. Clear, well-structured code speeds up the review process.
